# 评审任务书 · 横向对比评审

## 角色
你是横向对比评审员。你没有参与设计，没有设计者上下文；五个单版评审已由
独立评审员完成，你只基于他们的书面结论与产物做交叉比较。

## 前置读取
1. `prototypes/ux-2026-09/review/verdicts/` 下 5 份单版结论（a/b/c/d/e）
2. `prototypes/ux-2026-09/README.md` — 各版本哲学与 5 分钟体验剧本
3. `prototypes/ux-2026-09/DESIGN_CHECKLIST.md` — 通用基线
4. `prototypes/ux-2026-09/review/screenshots/` — 5 张主界面截图（自行目检布局密度/视觉层次）

## 评审任务
1. **排名**：综合单版评分与你的目检，给 5 个版本排总推荐度序，并给出「适合谁/什么场景」一行
2. **冲突仲裁**：单版结论之间如有互相矛盾的判断，指出并给出你的裁定（以代码/截图证据为准）
3. **合并建议**：用户最终只会维护一个正式版。给出「最终版应从哪个版本做骨架、从其他版本各搬哪些元素」的方案（≤5 条）
4. **风险**：合并回正式版时最可能翻车的 2-3 点

## 允许产出
- 只写 `prototypes/ux-2026-09/review/verdicts/_cross_compare.md`（≤60 行）
- **禁止修改任何代码**

## 结论格式
```
# 横向对比
排名: 1. … 2. … 3. … 4. … 5. …（每名一句话理由）
适合场景: A→… · B→… · C→… · D→… · E→…
仲裁: …（无则写"无冲突"）
合并方案: …
风险: …
```
