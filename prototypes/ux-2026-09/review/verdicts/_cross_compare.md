仲裁:
1. E「撤销按钮」三方言突：单版结论说无按钮、REPAIRS 说已修、截图上确实没有——代码裁定修复属实（e_ai_concierge/app.py:319-324），截图走的是 UX_SCENE=stage 演示路径（app.py:449-452 未传 undo_label），属截图误导；建议重制 stage 场景同步真实路径。
2. B README 剧本宣称「点 s/d 直改状态」 vs 单版判定键盘流任务不可达：修复后键位存在但仍作用鼠标选中的行动（REPAIRS 自认），裁定为"部分兑现"——合并时要么补键盘选中、要么改文档口径。
3. 各版评分均为修复前值，不可直接横向加减；本排名为修后加权结果（E 反馈 2→约 3，B 流畅 2→约 3.5）。

合并方案（骨架 A，≤5 条）:
1. 骨架取 A：捕获三路由（!/#/纯文字）+ 顺延条 + touch-once + 工作记录区原样保留为首页；A 的 3 个 P1 一并带走修掉（图标按钮加文字、顺延撤销改 ID 匹配别按文本删）。
2. 从 B 搬键位层：1/2/3/j/k + Ctrl+K 面板即文档 + `_set_typing` 焦点守卫；归档键必须补 undo_snackbar 后才准进门。
3. 从 C 搬收尾向导：A 已有顺延条，C 四步向导作为其展开形态（昨日未完成>0 时可进入、可跳过、带「今天已收尾过」记忆）；Check/Act 写 days/<日期>.md 镜像逻辑整体照搬。
4. 从 E 搬草稿卡与文件监听：三键草稿卡+失败不出卡+「生成中」加载态+watch_inbox 高置信常驻撤销；合并后接真实 provider 前必须先异步化。
5. 从 D 只搬两个元素：行动停滞红点标记与真实停滞天数（挂在 A/列表视图上）；画布本体缓发——先修「适应窗口」确认弹窗与布局 JSON 坏类型回落。

风险:
1. 同步 AI 调用是 A/C/E 共同的定时炸弹：fake 秒回掩盖一切，真实端点最长冻结 120s（runtime.py:90 超时）——合并版第一个真实端点实测大概率翻车，需异步任务+可取消+失败兜底。
2. B 键位注入 A 的输入框环境时，焦点守卫（typing 时键盘流让路）是必抄项不是可选项，否则捕获框里打「3」会误转计划。
3. E 高置信自动归档是全产品唯一红线偏离，合并时撤销入口若缩回 6 秒 snackbar（信息卡常驻按钮丢失），「可放心托付」定位将反噬信任；时间流只增不减的性能债需同步清。
