# 原型 UI 基线（DESIGN_CHECKLIST）

五个原型都必须满足的底线，也是评审子代理的验收清单。
背景：正式版最大的问题不是缺功能，而是「反馈与状态不可信」——死按钮、
回弹复选框、无保存反馈、整页重建丢状态，让用户不敢依赖界面。

## 每个原型必须做到

- [ ] **统一反馈**：所有写操作经 `ui_kit.tell()` 弹 snackbar（"已保存/已顺延/已归档"），落盘必须让用户知道
- [ ] **危险操作可撤销**：删除/自动追加走 `undo_snackbar()`（执行 + 撤销按钮），不打断手
- [ ] **空态引导**：每个列表空态说明"这里会有什么 + 一个引导动作"（`ui_kit.hint()`），不留白板
- [ ] **焦点回归**：捕获/新增提交后焦点自动回输入框，支持连续录入
- [ ] **多行编辑即存**：失焦即存 + Enter 提交 / Shift+Enter 换行，保存有微反馈
- [ ] **状态宁空勿假**：不显示假数据（没有活跃记录显示"—"而不是今天）；停滞天数是真实差值
- [ ] **统一语义色板**：绿=完成、蓝=进行中、琥珀=等待、红=停滞、灰=待开始（`ui_kit.STATUS_COLORS`）
- [ ] **AI 草稿红线**：AI 只产草稿，落盘必经人工确认（唯一例外：E 版高置信文件路由自动追加，必须可一键撤销）

## 各版本特有的验收点

- A：三种捕获路由（`!` / `#项目` / 纯文字）都有正确落点；顺延条只在昨日确有未完成时出现
- B：Ctrl+K 空查询时面板即完整命令文档；j/k 选择范围钳制不越界
- C：向导每步只问一件事；每步都可跳过；Check/Act 落 `days/<日期>.md` 镜像
- D：拖拽布局重启后保留；「适应窗口」可回网格；停滞卡片红框
- E：草稿卡三键齐全；高置信文件路由的通知卡必须带「撤销」
